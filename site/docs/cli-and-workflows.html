Developer Guide

CLI & Developer Workflows

Manage cloud workspaces from the web console or the standalone municode CLI (also aliased as workspaces). Every workspace command supports --json for scripting.

1. CLI setup & authentication

Install the self-contained binary for your workstation OS onto your PATH, set your team's HTTPS API URL, and log in through your browser:

shell 
municode config set-api-url https://api.example.com
municode login

For headless scripts, supply MUNICODE_API_URL and a scoped API key via MUNICODE_TOKEN (using workspaces:read for inspection and workspaces:write only when starting, stopping, or mutating workspaces).

2. Persistent workspace lifecycle

create registers a workspace in a stopped state—compute only starts when you run start. Stopping a workspace destroys the VM so compute billing stops while keeping your persistent volume intact.

shell 
# List available VM images, profiles, and plans in your organization
municode workspaces selections

# Create a workspace with a 60 GB persistent volume and 90-minute idle auto-stop
municode workspaces create \
  --name backend-dev \
  --image <image-id> \
  --profile Standard \
  --plan <plan-id> \
  --volume-gb 60 \
  --idle-timeout 90

# Start the VM, check status, and open the workspace in your browser
municode workspaces start <workspace-id>
municode workspaces status <workspace-id>
municode workspaces open <workspace-id>

# Queue a larger VM plan or updated image for the next start
municode workspaces resize-next-start <workspace-id> \
  --generation 1 --image <image-id> --profile Heavy --plan <larger-plan-id>

# Stop compute (retains your volume) or permanently delete the workspace
municode workspaces stop <workspace-id>
municode workspaces delete <workspace-id> --confirm-permanent-deletion

3. Ephemeral Git-backed VMs

When you want an isolated machine for a branch, experiment, or parallel coding-agent run, launch an ephemeral VM. It attaches no persistent volume, clones your target repository and commit onto a fresh work branch, and blocks shutdown in awaiting_git_save if unpushed commits would be lost.

shell 
municode workspaces launch <workspace-id> \
  --image <image-id> \
  --profile Standard \
  --plan <plan-id> \
  --repository https://github.com/org/repo.git \
  --base-ref refs/heads/main \
  --base-commit <commit-sha> \
  --push-authorized \
  --acknowledge-ignored-data-loss

4. Common questions

Can we customize the OS, SDKs, and coding agents in our workspaces?

Yes. Your organization registers the VM images it wants to run—choosing the operating system, language toolchains, and coding agents (such as Codex, Claude Code, GitHub Copilot CLI, Antigravity, or Muse Code). Updating to a new image preserves your persistent workspace volume across starts.

How do live web previews work for apps running inside a VM?

Named preview ports configured on your installation can be launched directly from the console or API. Each preview receives its own authenticated subdomain separate from the workspace IDE so cookies, storage, and WebSockets never collide.

What happens when a workspace hits its idle timeout?

After the configured period without active input or task leases, Municode cleanly stops the VM and releases cloud compute while keeping your persistent volume intact. You can adjust the timeout per workspace with municode workspaces idle-timeout or pass --keep-running when needed.

For additional details, see docs/user.md in the repository.
