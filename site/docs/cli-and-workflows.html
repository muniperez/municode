CLI and workflows

Manage workspaces from the web console or the standalone municode CLI. All workspace commands accept --json.

1. CLI setup & authentication

Place the CLI binary for your OS on your PATH, configure your installation's HTTPS API URL, and authenticate in your browser:

Shell 
$ municode config set-api-url https://api.example.com
$ municode login

For scripts, set MUNICODE_API_URL and pass a scoped key via MUNICODE_TOKEN (workspaces:read for status queries; workspaces:write for mutations).

2. Persistent workspaces

create allocates the workspace record in a stopped state; compute only starts on start. stop deletes the cloud VM and retains the primary volume.

Shell 
$ municode workspaces selections
$ municode workspaces create \
    --name backend-dev \
    --image <image-id> \
    --profile Standard \
    --plan <plan-id> \
    --volume-gb 60 \
    --idle-timeout 90
$ municode workspaces start <workspace-id>
$ municode workspaces open <workspace-id>

# Queue a different plan or image for the next start:
$ municode workspaces resize-next-start <workspace-id> \
    --generation 1 --image <image-id> --profile Heavy --plan <larger-plan-id>

# Stop compute or permanently delete the workspace and its volume:
$ municode workspaces stop <workspace-id>
$ municode workspaces delete <workspace-id> --confirm-permanent-deletion

3. Ephemeral Git-backed VMs

Ephemeral VMs attach no persistent volume. They clone an authorized repository and commit onto a per-generation branch and enter awaiting_git_save on stop if unpushed commits remain.

Shell 
$ municode workspaces launch <workspace-id> \
    --image <image-id> \
    --profile Standard \
    --plan <plan-id> \
    --repository https://github.com/org/repo.git \
    --base-ref refs/heads/main \
    --base-commit <commit-sha> \
    --push-authorized \
    --acknowledge-ignored-data-loss

4. Operational notes

Customizing OS images, SDKs, and coding agents

Organizations register the VM images they want to admit, choosing the operating system, language toolchains, and coding agents. Moving a persistent workspace to a newer image via resize-next-start keeps the existing volume attached on the next boot.

Application preview URLs

Named loopback preview ports configured on the worker can be launched from the console or API. Each preview service runs on its own subdomain separate from the workspace IDE.

Idle timeouts

After the configured window without active input or task leases, the worker stops the VM and retains the persistent volume. Configure per-workspace timeouts with municode workspaces idle-timeout or disable idle stop with --keep-running.

See docs/user.md in the repository for additional details.
