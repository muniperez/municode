System architecture

Municode separates control-plane state (Municode.Api), cloud reconciliation and SSH forwarding (Municode.Worker), and browser session proxying (Municode.Gateway).

1. Control-plane components & network boundaries

Services run across segmented internal networks so the edge gateway does not have access to the database or cloud-provider secret store:

  • Reverse proxy & console: Serves the static dashboard and terminates TLS for the console, API, and wildcard workspace domains, requesting wildcard certificates on demand only for authorized workspace hostnames.
  • Municode Gateway: Redeems single-use launch codes for host-only cookies, rechecks active WebSocket sessions against the API, and forwards traffic onto the internal relay network.
  • Municode API: Manages organizations, RBAC, admitted images and plans, lifecycle operations, VM enrollment, and short-lived Git credentials.
  • Municode Worker: Claims lifecycle jobs, provisions cloud VMs and volumes, pins each VM generation's SSH host key, and binds local SSH port forwards for the gateway.

4. Repository layout

  • src/Municode.Api — Authentication, organization RBAC, image/plan admission, and workspace lifecycle API.
  • src/Municode.Worker — Cloud VM/volume reconciliation, guest bootstrap, and SSH port forwarding.
  • src/Municode.Gateway — Launch-code redemption, origin isolation, and HTTP/WebSocket session relay.
  • src/Municode.Cli — Standalone municode / workspaces CLI and seed bootstrap commands.
  • modules/dashboard — Web console frontend.
  • templates/development-workspaces — Reference guest runtime scripts and image builder template.
