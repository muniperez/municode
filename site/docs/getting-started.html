Control-plane setup

Provision a fresh control-plane host with municode seed, or install a verified release archive onto an existing host running Docker Compose.

1. Provisioning with municode seed

municode seed provisions one control-plane host from a signed release. It quotes recurring costs before creating resources, records progress in a local journal so interrupted runs can resume, and pauses for out-of-band SSH host fingerprint verification and DNS setup.

The bootstrap provider token is read only from a local owner-only file and is never copied to the control-plane server or stored as a workspace provider account. Seed does not create workspace VMs.

Commands

Shell 
$ install -m 600 /dev/null /protected/provider.token
$ municode seed plan \
    --provider <provider> --region <region> --size <size> \
    --dashboard-hostname console.example.com \
    --api-hostname api.example.com \
    --gateway-domain workspaces.example.com \
    --release municode-vX.Y.Z \
    --credential-file /protected/provider.token
$ municode seed apply <operation> \
    --credential-file /protected/provider.token \
    --approve <approval-digest>
$ municode seed resume <operation> \
    --credential-file /protected/provider.token \
    --confirm-console-fingerprint SHA256:...

Required DNS records

Public DNS records pointing to the control-plane host
Record Type Target Purpose
console.example.com A Control-plane public IPv4 Web console UI
api.example.com A Control-plane public IPv4 Control-plane API & CLI endpoint
*.workspaces.example.com A Control-plane public IPv4 Subdomains for workspace IDE & preview sessions

2. Manual installation with Docker Compose

On an existing server with Docker Engine and Compose v2, first set the public hostnames and installation ID in /etc/municode/config/operator.env as shown in the operator guide. Then run:

Shell 
$ sha256sum --check --strict checksums.txt
$ bundle_sha256="$(sha256sum municode-X.Y.Z-linux-any.tar.gz | cut -d ' ' -f 1)"
$ tar -xzf municode-X.Y.Z-linux-any.tar.gz && cd municode-X.Y.Z
$ sudo ./install.sh --bundle-sha256 "$bundle_sha256"
$ sudo municode-compose up -d postgres openbao
$ OPENBAO_ROOT_TOKEN_FILE=/protected/root-token \
    sudo --preserve-env=OPENBAO_ROOT_TOKEN_FILE municode-compose --profile maintenance run --rm openbao-configure
$ sudo municode-compose up database-initialize kratos-migrate api-migrate && sudo municode-compose up -d

See docs/operator.md for secret backup custody, first-owner bootstrap token generation, and upgrade steps.

3. Registering provider accounts, images & plans

After completing first-owner setup, register capacity before enabling workspace creation:

  1. Register a cloud provider account in the console or via /api/providers (credentials are stored in the control plane's secret store).
  2. Register one or more VM images containing the operating system, SDKs, and coding agents your organization uses. A reference guest runtime and image builder template is available in templates/development-workspaces.
  3. Admit compute plans and cost estimates so developers can select them in the console or CLI.
