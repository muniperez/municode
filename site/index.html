Self-Hosted Cloud Workspaces

Cloud coding VMs you control.

Municode is a self-hosted control plane that spins up dedicated coding VMs in your own cloud account. Bring the OS, toolchain, and coding agents you want, work from your browser or CLI, and stop VMs when idle without losing your workspace.

What Is Municode

Remote dev environments without giving up control.

Offload heavy builds, parallel branches, and coding agents from your laptop onto dedicated cloud VMs—while keeping infrastructure, images, and credentials entirely on your own stack.

01 // SELF-HOSTED

Runs on your own infrastructure

Municode is a standalone system with built-in authentication, secret storage, web console, API, and gateway. No hosted SaaS account or external relay service is required.

02 // YOUR ENVIRONMENT

Bring the OS, image & tools you want

Teams qualify and register their own VM images and machine sizes—pick the operating system, language runtimes, and coding agents that match your workflow.

03 // ON-DEMAND COMPUTE

Stop the VM, keep your workspace

Stopping a workspace releases the VM so hourly compute billing stops immediately. Your persistent workspace volume stays intact and reattaches the next time you start—even if you resize the VM.

04 // RETAINED OR EPHEMERAL

Long-lived workspaces or clean Git sandboxes

Use a persistent primary workspace for daily development, or spin up disposable Git-backed VMs tied to a specific repository and commit for isolated tasks and agent runs.

How To Get Started

Up and running in three steps.

Deploy a self-hosted control plane for your team, connect as an engineer to spin up a workspace, or run Municode locally from source.

  1. 1

    Plan your control plane

    Verify the release and preview exact cloud costs before creating any infrastructure.

    shell 
    workspaces seed plan \
  --provider <provider> --region <region> --size <size> \
  --dashboard-hostname console.example.com \
  --api-hostname api.example.com \
  --gateway-domain workspaces.example.com \
  --release workspaces-vX.Y.Z \
  --credential-file /path/to/provider.token
  2. 2

    Apply & connect DNS

    Approve the plan to provision the control-plane host, point your DNS records at it, and resume automated HTTPS setup.

    shell 
    workspaces seed apply <operation-id> \
  --credential-file /path/to/provider.token \
  --approve <plan-digest>

workspaces seed resume <operation-id> \
  --credential-file /path/to/provider.token \
  --confirm-console-fingerprint SHA256:...
  3. 3

    Finish console setup & register your VM image

    Complete first-owner sign-in at https://console.example.com/setup, connect your cloud account, and register the VM image and machine plans your team wants to use.

    Detailed Setup & Manual Host Guide →

  1. 1

    Sign in from the CLI (or web console)

    Point the CLI at your team's API URL and approve login in your browser.

    shell 
    municode config set-api-url https://api.example.com
municode login
  2. 2

    Create & start a workspace

    Choose an available image and machine plan, create your workspace, and boot its VM.

    shell 
    municode workspaces selections

municode workspaces create \
  --name my-workspace \
  --image <image-id> \
  --profile Standard \
  --plan <plan-id> \
  --volume-gb 50

municode workspaces start <workspace-id>
  3. 3

    Open in your browser & stop when done

    Open your workspace session over HTTPS. When finished, stop it to release the VM while keeping your persistent volume.

    shell 
    municode workspaces open <workspace-id>

# Release compute when finished (files stay on your volume):
municode workspaces stop <workspace-id>

  1. 1

    Build & run the test suite

    Build the solution and run the synthetic test suite locally—no cloud account required.

    shell 
    dotnet build Workspaces.slnx -c Release
dotnet test Workspaces.slnx -c Release --no-build
  2. 2

    Boot a local API instance

    Run local migrations and start the API against a local database on http://127.0.0.1:5080.

    shell 
    dotnet run --project src/Workspaces.Api -c Release --no-build -- migrate
dotnet run --project src/Workspaces.Api -c Release --no-build -- --urls http://127.0.0.1:5080

How It Works

Private session routing & decoupled storage.

Municode separates session routing from VM compute and separates VM compute from your persistent files—so workspaces stay private and idle machines cost nothing in compute.
