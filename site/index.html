Self-hosted cloud development workspaces

Municode is an open-source control plane and runtime that provisions development VMs in your cloud account. Register VM images with the operating system, SDKs, and coding agents your team uses, and connect through the web console or CLI.

Get started Documentation

What is Municode

A standalone system for running remote coding environments without relying on a hosted workspace SaaS. All control-plane components—API, worker, gateway, web console, identity, database, and secret storage—run on infrastructure you operate.

Control plane

Manages organizations, user authentication, encrypted provider credentials, machine plans, and workspace state.

Custom VM images

Admins admit the VM images and machine sizes developers can select, with whatever OS and tooling a team needs.

Persistent & ephemeral VMs

Primary workspaces attach a persistent volume across boots; ephemeral VMs clone a target Git repository and commit onto a clean branch.

Web console & CLI

Launch browser IDE and preview sessions from the dashboard, or script workspace operations with municode.

How it works

The API records desired state, the worker reconciles VMs and volumes in your cloud account, and the gateway proxies authenticated traffic to running workspaces.

  • Authenticated launch: Opening an IDE or preview service mints a single-use launch URL on a dedicated subdomain, exchanged by the gateway for a host-only session cookie.
  • Private SSH forwarding: The worker connects to each VM with a per-boot pinned host key and forwards traffic to loopback services inside the guest.
  • Stop and resume: Stopping a workspace deletes the cloud VM (manually or after an idle timeout) and retains the volume; starting provisions a new VM generation—optionally with a different machine size or image—and remounts the volume.
  • Scratch vs. persistent storage: Build outputs and package caches stay on the VM's local disk rather than the persistent volume.

Get started

Bootstrap a control plane, connect to an existing installation, or build from source.

Shell 
$ municode seed plan \
    --provider <provider> --region <region> --size <size> \
    --dashboard-hostname console.example.com \
    --api-hostname api.example.com \
    --gateway-domain workspaces.example.com \
    --release municode-vX.Y.Z \
    --credential-file /protected/provider.token

$ municode seed apply <operation> \
    --credential-file /protected/provider.token --approve <digest>

$ municode seed resume <operation> \
    --credential-file /protected/provider.token \
    --confirm-console-fingerprint SHA256:...
  1. seed plan verifies the signed release archive and prints the provider's recurring cost quote before creating resources.
  2. seed apply provisions the control-plane host once you pass the plan's approval digest.
  3. seed resume pins the host's console SSH fingerprint, waits for DNS, starts the stack over HTTPS, and saves the one-time /setup token locally.
Control-plane setup guide
Shell 
$ municode config set-api-url https://api.example.com
$ municode login
$ municode workspaces selections

$ municode workspaces create --name dev \
    --image <image-id> --profile Standard --plan <plan-id> --volume-gb 50

$ municode workspaces start <workspace-id>
$ municode workspaces open <workspace-id>
$ municode workspaces stop <workspace-id>
  1. Point the CLI at your installation's API origin and run municode login to approve access in your browser.
  2. Check admitted images and plans with selections, create a workspace, and run start to provision the VM.
  3. Use open to launch the browser session and stop to shut down the VM when done.
CLI and workflows guide
Shell 
$ git clone https://github.com/muniperez/municode.git && cd municode
$ dotnet build Municode.slnx -c Release
$ dotnet test Municode.slnx -c Release --no-build

$ dotnet run --project src/Municode.Api -c Release --no-build -- migrate
$ dotnet run --project src/Municode.Api -c Release --no-build -- --urls http://127.0.0.1:5080
  1. Build Municode.slnx and run the synthetic test suites locally with the .NET 10 SDK and Python 3.11+.
  2. Run local SQLite migrations and start Municode.Api on 127.0.0.1:5080.
  3. Check /health locally, or inspect the service boundaries and runtime contracts in the architecture docs.
